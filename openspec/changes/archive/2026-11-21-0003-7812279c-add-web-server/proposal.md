# Proposal

## Why

Сейчас калькулятор `h1` доступен только как CLI-приложение: каждый расчёт
требует запуска процесса и передачи JSON через `--config`. В рабочей копии
уже есть незавершённый черновик HTTP-сервера на Boost.Asio, но он не выполняет
свою функцию: ручка `POST /h1/task` возвращает эхо тела запроса вместо
результата расчёта, не имеет JSON-контракта, конфигурации и не покрыта тестами.
Нужно довести черновик до полноценного серверного режима, сохранив
существующее CLI-приложение без изменений.

## What Changes

- Дорабатывается модуль `h1::io_server`: ручка `POST /h1/task` принимает JSON
  операции, выполняет расчёт через существующие `jsonp` / `calc` /
  `calculation::CalculationService`, сохраняет результат в PostgreSQL и кеш.
- Вводится JSON-контракт ответа: успешный расчёт — HTTP 200 и JSON с
  операндами, операцией, результатом и признаком попадания в кеш; любая ошибка
  (невалидный JSON, ошибка вычисления, внутренняя ошибка) — HTTP 500 и JSON с
  текстом ошибки.
- Исправляется дефект многопоточной работы с БД: в `DBManager` повторный
  `lock_guard` на одном мьютексе приводит к взаимной блокировке при вставке
  записи; доступ к `PGconn` и кешу сериализуется корректно.
- Добавляется конфигурация сервера через CLI (`--host`, `--port`, `--threads`,
  `--verbose`, `--help`) с переопределением через переменные окружения
  `H1_SERVER_HOST`, `H1_SERVER_PORT`, `H1_SERVER_THREADS`.
- Сервер при старте прогревает кеш из БД тем же способом, что и CLI-приложение.
- Исправляется инициализация логгера в `cmd/server_main.cpp` (уровень
  логирования и имя логгера сейчас вычисляются, но не применяются).
- Сервер поставляется отдельным бинарником `h1Server`, systemd-юнитом
  `h1-server.service` и deb-пакетом `h1-server`. Из упаковки удаляются
  CLI-бинарник `h1`, юнит `h1.service` и конфиг `/etc/h1/h1.env`; CLI остаётся
  только как сборочная цель для разработки.
- **Согласованное отступление от ограничения ДЗ-3:** сервер остаётся
  многопоточным (пул потоков Boost.Asio). Владелец проекта явно подтвердил это
  решение; запрет многопоточности из `openspec/context/constraints.md`
  продолжает действовать для остального кода, но не для серверного режима.
- **BREAKING** для черновика: ответ ручки `POST /h1/task` меняется с эха
  запроса на JSON-результат расчёта. Внешних пользователей у черновика нет,
  поэтому отдельная миграция не требуется.

## Capabilities

### New Capabilities

- `http-api`: наблюдаемое поведение HTTP-сервера — единственная ручка
  `POST /h1/task`, JSON-контракт запроса/ответа, коды 200/500, сохранение
  результатов в БД и кеш, конфигурация и запуск серверного режима.

### Modified Capabilities

- `deb-packaging`: пакет переименовывается в `h1-server` и содержит только
  серверный бинарник `h1Server`, юнит `h1-server.service` и конфиг
  `/etc/h1/h1-server.env`; CLI-артефакты и разовый `h1.service` удаляются из
  поставки.

## Impact

- **Код**: `include/h1/io_server/` и `src/io_server/` (handlers, response,
  router, connection, io_server), `cmd/server_main.cpp`, `src/db/manager.cpp`
  (исправление блокировки), `src/local_cache/local_cache.cpp` (проверка
  потокобезопасности).
- **CMakeLists.txt**: цель `h1Server` уже добавлена черновиком; требуется
  установка бинарника, включение новых тестовых файлов, отсутствие регрессий
  сборки `h1` и `h1_test`.
- **Поставка**: `packaging/systemd/h1-server.service`,
  `packaging/etc/h1/h1-server.env`, install-правила и состав deb-пакета.
- **Документация**: `README.md` — запуск сервера, контракт API, конфигурация,
  примеры `curl`.
- **Тесты**: новые GoogleTest-файлы для роутера, хендлера и конфигурации
  сервера; существующие тесты должны оставаться зелёными.
- **Совместимость**: CLI-приложение `h1` собирается и работает как раньше, но
  больше не входит в deb-пакет; схема БД и формат кеша не меняются.
- **Ограничения**: многопоточность разрешена только в серверном режиме;
  RAII, отказ от libpqxx, собственная обёртка над libpq сохраняются.
