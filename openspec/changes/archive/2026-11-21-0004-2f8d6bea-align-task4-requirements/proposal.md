# Proposal

## Why

Change `0003-7812279c-add-web-server` довёл проект до рабочего HTTP-сервера, но
аудит по `docs/task4.md` выявил расхождения: конфигурация допускает один поток
обработки, нет сетевого тестового клиента, который проверяет именно результат
расчёта, и не выполнена обязательная проверка ThreadSanitizer. Этот change
закрывает оставшиеся технические требования ДЗ-4, не меняя уже реализованную
функциональность расчёта.

Требование ДЗ-4 о четырёх отдельных документах с планами не применяется:
проект ведёт все изменения через OpenSpec-спеки (proposal/design/specs/tasks),
а выбор способа разработки и оформления планов остаётся за разработчиком.

## What Changes

- `ServerConfig` начинает требовать минимум **2 потока** обработки
  (`--threads`/`H1_SERVER_THREADS`); значения меньше 2 отклоняются с понятной
  ошибкой. `IOServer::run()` дополнительно страхует `max(2, threads)`.
- В `IOServer` добавляются публичные `stop()` и `port()` для управления
  тестовым сервером из GTest; сигнальная обработка остаётся на пуле потоков
  `io_context` (отдельный signal-поток не вводится — по текущей архитектуре
  один из потоков пула принимает `SIGTERM`).
- Добавляется сетевой тестовый клиент на GoogleTest + Boost.Asio
  (`src/test_http_server.cpp`): поднимает `IOServer` на локальном эфемерном
  порту с `TaskManagerHandler` и mock-БД/кешем, отправляет `POST /h1/task`,
  проверяет HTTP-статус, `Content-Type` и **тело JSON с результатом**.
  Ожидание готовности сервера — busy-цикл с дедлайном, без `sleep_for`.
- Добавляется CMake-опция `H1_USE_TSAN` и target `tsan-tests`, добавляющие
  `-fsanitize=thread`; итоговая проверка прогоняется на финальной версии
  сервиса.
- Обновляются README, `manual-tests.md` и задачи проверки.
- Отдельные четыре документа `docs/task4-plan-*.md` не создаются: планы
  ведутся в OpenSpec, это осознанное решение разработчика.

## Capabilities

### New Capabilities

- `service-quality`: гарантии готовности серверного режима к требованиям
  ДЗ-4 — минимальное число потоков, наличие сетевого тестового клиента с
  проверкой результата, ThreadSanitizer-проверка.

### Modified Capabilities

- (нет; `http-api` и `deb-packaging` уже описаны в change 0003)

## Impact

- **Код**: `include/h1/io_server/io_server.hpp`,
  `src/io_server/io_server.cpp` (публичные `stop()`/`port()`, минимум
  потоков), `src/io_server/server_config.cpp` (валидация `threads >= 2`).
- **Тесты**: новый `src/test_http_server.cpp`; регистрация в
  `add_executable(h1_test ...)`; существующие тесты не меняют поведение.
- **Сборка**: `CMakeLists.txt` — опция `H1_USE_TSAN`, target `tsan-tests`,
  линковка Boost.Asio для тестового клиента; `Makefile` — команда `make tsan`.
- **Документация**: только `README.md` и артефакты OpenSpec-change. Четыре
  отдельных плановых документа не создаются (решение разработчика).
- **Зависимость**: change предполагает, что 0003 уже применён (HTTP-сервер,
  `h1-server` deb-пакет, `h1-server.service`).
- **Ограничения**: многопоточность в серверном режиме уже согласована в 0003;
  RAII, libpq-обёртка и запрет libpqxx сохраняются.
