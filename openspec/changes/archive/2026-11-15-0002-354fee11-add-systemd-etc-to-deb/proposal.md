# Proposal

## Why

Пакет `h1` раньше ставил только бинарник `/usr/bin/h1`, поэтому запуск через
systemd был невозможен: юнита нет, переменные окружения для подключения к
PostgreSQL приходилось создавать вручную. Изменения уже внесены в репозиторий
(юнит, конфиг в `/etc`, скрипты сопровождения) и проверены на реальной
установке, но живут без спеки — их нужно оформить дельтой к существующей
capability `deb-packaging`, чтобы главный spec перестал противоречить
фактическому составу пакета.

## What Changes

- **Модифицируется требование «Состав пакета»**: пакет больше не содержит
  «только `/usr/bin/h1`». Теперь в него входят systemd-юниты из
  `packaging/systemd/` (устанавливаются в `/usr/lib/systemd/system`) и конфиг
  окружения `/etc/h1/h1.env`.
- Новое требование: systemd-юниты формируются автоматически из каталога
  `packaging/systemd/` (`*.service`, `*.timer`, `*.socket`); добавление нового
  юнита не требует правок CMake. Механизм отключается опцией
  `H1_INSTALL_SYSTEMD_UNITS=OFF`.
- Новое требование: пакет содержит systemd-юнит `h1.service` (`Type=oneshot`,
  разовый расчёт), который читает переменные подключения к БД из
  `/etc/h1/h1.env` (`EnvironmentFile=-/etc/h1/h1.env`) и запускается
  `systemctl start h1`.
- Новое требование: `/etc/h1/h1.env` регистрируется как conffile
  (`packaging/deb/conffiles`) — правки пользователя сохраняются при обновлении
  пакета.
- Новое требование: при установке/обновлении пакета выполняется
  `systemctl daemon-reload` и юнит включается в автозагрузку
  (`systemctl enable h1` в postinst); при удалении юнит выводится из
  автозагрузки (prerm) и выполняется `daemon-reload` (postrm), чтобы
  systemd сразу видел добавленные/удалённые юниты.
- Документация: README дополняется разделом про systemd-юниты и конфиг
  `/etc/h1/h1.env` (уже сделано — задача фиксирует проверку).

## Capabilities

### New Capabilities

- (нет — поведение пакета уже принадлежит существующей capability)

### Modified Capabilities

- `deb-packaging`: требование «Состав пакета» переписывается (бинарник +
  systemd-юниты + conffile `/etc/h1/h1.env` вместо «только `/usr/bin/h1`»);
  добавляются требования о механизме юнитов, о юните `h1.service`, о conffile
  и о `daemon-reload` при установке/удалении пакета. Требования «Зависимости
  пакета», «Установка через apt-get», «Установленный пакет работает как
  приложение из репозитория» не меняются.

## Impact

- **CMakeLists.txt**: новые install-правила (юниты, конфиг), опция
  `H1_INSTALL_SYSTEMD_UNITS`, переменная `H1_SYSTEMD_UNIT_DIR`,
  `H1_SYSCONF_DIR`, `CPACK_DEBIAN_PACKAGE_CONTROL_EXTRA` (postinst, postrm,
  conffiles). Исходники C++ и списки `H1_CORE_SOURCES` не затрагиваются.
- **Новые файлы репозитория**: `packaging/systemd/h1.service`,
  `packaging/etc/h1/h1.env`, `packaging/deb/postinst`, `packaging/deb/postrm`,
  `packaging/deb/conffiles`, раздел в `README.md`.
- **Установленная система**: новые пути `/usr/lib/systemd/system/h1.service`,
  `/etc/h1/h1.env`; юнит после установки включён в автозагрузку (enabled,
  расчёт выполняется при каждой загрузке; решение подтверждено владельцем
  проекта в apply-фазе), отключается `systemctl disable h1`.
- **Совместимость**: обновление со старой версии пакета сохранит
  пользовательские правки `/etc/h1/h1.env` (conffile). Удаление пакета
  убирает юниты; поведение БД-зависимостей не меняется.
