# Spec Delta: deb-packaging

## MODIFIED Requirements

### Requirement: Состав пакета
Пакет `h1` SHALL устанавливать: исполняемый файл приложения в `/usr/bin/h1`,
systemd-юниты в `/usr/lib/systemd/system` и файл окружения `/etc/h1/h1.env`,
зарегистрированный как conffile. Заголовки, статическая библиотека `h1_core`
и тесты в пакет НЕ входят.

#### Scenario: Бинарник доступен в PATH
- **WHEN** пакет установлен
- **THEN** команда `h1` доступна в PATH и `h1 --help` выводит справку

#### Scenario: Юнит установлен в системный каталог
- **WHEN** пакет установлен
- **THEN** файлы юнитов из состава пакета присутствуют в `/usr/lib/systemd/system` (например, `h1.service`)

#### Scenario: Конфиг установлен в /etc
- **WHEN** пакет установлен
- **THEN** файл `/etc/h1/h1.env` присутствует и зарегистрирован в списке conffiles пакета

#### Scenario: В пакете нет посторонних файлов
- **WHEN** пользователь просматривает содержимое установленного пакета
- **THEN** в пакете присутствуют только `/usr/bin/h1`, файлы юнитов в `/usr/lib/systemd/system` и `/etc/h1/h1.env` (плюс штатные служебные записи dpkg); заголовки, статическая библиотека `h1_core`, тесты и docker-compose в пакет не входят

## ADDED Requirements

### Requirement: Автоматическое включение systemd-юнитов в пакет
Сборка пакета SHALL автоматически включать все файлы с расширениями
`.service`, `.timer` и `.socket` из каталога репозитория
`packaging/systemd/` в `/usr/lib/systemd/system`, без правок CMake при
добавлении нового юнита. Включение юнитов SHALL управляться опцией сборки
`H1_INSTALL_SYSTEMD_UNITS` (по умолчанию включено).

#### Scenario: Новый юнит попадает в пакет без правок CMake
- **WHEN** в каталог `packaging/systemd/` добавлен файл `*.service`, `*.timer` или `*.socket`, после чего пакет пересобирается и устанавливается
- **THEN** добавленный файл появляется в `/usr/lib/systemd/system` вместе с остальным содержимым пакета

#### Scenario: Отключение установки юнитов опцией
- **WHEN** сборка конфигурируется с `-DH1_INSTALL_SYSTEMD_UNITS=OFF` и пакет собирается
- **THEN** файлы юнитов не входят в пакет, остальной состав (бинарник, конфиг `/etc/h1/h1.env`) не меняется

### Requirement: Разовый расчёт через systemd-юнит
Пакет SHALL содержать юнит `h1.service` (`Type=oneshot`), который выполняет
один расчёт, заданный в `ExecStart`, и завершается. Юнит SHALL читать
переменные окружения подключения к PostgreSQL из `/etc/h1/h1.env`, при этом
отсутствие файла не препятствует старту юнита.

#### Scenario: Успешный расчёт через systemctl
- **WHEN** на машине с доступным PostgreSQL и настроенным `/etc/h1/h1.env` выполняется `systemctl start h1`
- **THEN** юнит отрабатывает расчёт (результат виден в `journalctl -u h1`) и переходит в состояние `inactive (dead)` без ошибок

#### Scenario: Юнит работает без файла окружения
- **WHEN** файл `/etc/h1/h1.env` отсутствует и выполняется `systemctl start h1`
- **THEN** юнит запускается (старт не блокируется); при недоступных переменных подключения к БД приложение завершается с ошибкой подключения, видимой в `journalctl -u h1`

#### Scenario: Юнит включается при установке
- **WHEN** пакет установлен на машине с работающим systemd
- **THEN** юнит `h1.service` включён в автозагрузку (enabled) и выполняется при каждой загрузке машины; отключить можно вручную `systemctl disable h1`

### Requirement: Конфигурация окружения как conffile
Файл `/etc/h1/h1.env` SHALL быть зарегистрирован в списке conffiles пакета:
dpkg SHALL сохранять правки пользователя при обновлении пакета и SHALL
сообщать о конфликте вместо молчаливой перезаписи.

#### Scenario: Правки сохраняются при обновлении
- **WHEN** пользователь изменил `/etc/h1/h1.env` (реальные параметры БД) и установил обновлённую версию пакета
- **THEN** правки сохраняются (dpkg оставляет пользовательскую версию или явно запрашивает решение о конфликте)

### Requirement: Автовключение юнита при установке и отключение при удалении
Пакет SHALL включать юнит `h1.service` в автозагрузку при установке
(`systemctl enable` в postinst) и отключать при удалении пакета
(`systemctl disable` в prerm), чтобы после удаления не оставались
висячие ссылки автозагрузки.

#### Scenario: Юнит в автозагрузке после установки
- **WHEN** пакет установлен на машине с работающим systemd
- **THEN** `systemctl is-enabled h1` отвечает `enabled`

#### Scenario: Автозагрузка снята при удалении
- **WHEN** выполняется удаление пакета
- **THEN** юнит выведен из автозагрузки до удаления файла юнита; после удаления `systemctl is-enabled h1` не отвечает `enabled`

### Requirement: Актуальность состояния systemd при установке и удалении
Пакет SHALL выполнять `systemctl daemon-reload` после установки/обновления и
после удаления, чтобы systemd сразу видел добавленные или удалённые юниты
без ручной перезагрузки демона.

#### Scenario: Юнит виден сразу после установки
- **WHEN** пакет установлен на машине с работающим systemd
- **THEN** `systemctl start h1` работает без предварительного ручного `daemon-reload`

#### Scenario: Юнит исчезает сразу после удаления
- **WHEN** выполняется удаление пакета на машине с работающим systemd
- **THEN** файлы юнитов удалены из `/usr/lib/systemd/system` и systemd больше не видит юнит без ручного `daemon-reload`
