# deb-packaging Specification

## Purpose

Дистрибуция приложения h1 в виде deb-пакета: пользователи Ubuntu 22.04/24.04
получают готовый бинарник без сборки из исходников, установка выполняется
командой `apt-get install ./h1_*.deb`.

## Requirements

### Requirement: Сборка deb-пакета из CMake-проекта
Проект SHALL предоставлять способ собрать deb-пакет одной командой из
конфигурированной CMake-сборки без ручных правок метаданных. Имя пакета —
`h1-server`, версия пакета SHALL повторять версию проекта
(`project(h1 VERSION ...)`), архитектура — amd64.

#### Scenario: Сборка пакета
- **WHEN** разработчик конфигурирует и собирает проект (cmake + cmake --build) и запускает сборку пакета
- **THEN** в каталоге сборки появляется файл `h1-server_<версия>_amd64.deb`

#### Scenario: Версия пакета соответствует версии проекта
- **WHEN** версия проекта в CMake меняется
- **THEN** имя и версия собранного deb-пакета обновляются автоматически, без правки метаданных пакета

### Requirement: Состав пакета
Пакет `h1-server` SHALL устанавливать только серверные артефакты:
исполняемый файл `/usr/bin/h1Server`, systemd-юнит
`/usr/lib/systemd/system/h1-server.service` и файл окружения
`/etc/h1/h1-server.env`, зарегистрированный как conffile. CLI-бинарник `h1`,
заголовки, статическая библиотека `h1_core` и тесты в пакет НЕ входят.

#### Scenario: Бинарник доступен в PATH
- **WHEN** пакет установлен
- **THEN** команда `h1Server` доступна в PATH и `h1Server --help` выводит
  справку

#### Scenario: CLI-бинарник отсутствует
- **WHEN** пакет установлен
- **THEN** команда `h1` не устанавливается пакетом

#### Scenario: Юнит установлен в системный каталог
- **WHEN** пакет установлен
- **THEN** файл `/usr/lib/systemd/system/h1-server.service` присутствует

#### Scenario: Конфиг установлен в /etc
- **WHEN** пакет установлен
- **THEN** файл `/etc/h1/h1-server.env` присутствует и зарегистрирован в
  списке conffiles пакета

#### Scenario: В пакете нет посторонних файлов
- **WHEN** пользователь просматривает содержимое установленного пакета
- **THEN** в пакете присутствуют только `/usr/bin/h1Server`, файл юнита
  `/usr/lib/systemd/system/h1-server.service` и
  `/etc/h1/h1-server.env` (плюс штатные служебные записи dpkg); CLI-бинарник
  `h1`, заголовки, статическая библиотека `h1_core`, тесты и docker-compose
  в пакет не входят

### Requirement: Автоматическое включение systemd-юнитов в пакет
Сборка пакета SHALL автоматически включать все файлы с расширениями
`.service`, `.timer` и `.socket` из каталога репозитория
`packaging/systemd/` в `/usr/lib/systemd/system`, без правок CMake при
добавлении нового юнита. Включение юнитов SHALL управляться опцией сборки
`H1_INSTALL_SYSTEMD_UNITS` (по умолчанию включено).

#### Scenario: Новый юнит попадает в пакет без правок CMake
- **WHEN** в каталог `packaging/systemd/` добавлен файл `*.service`, `*.timer` или `*.socket`, после чего пакет пересобирается и устанавливается
- **THEN** добавленный файл появляется в `/usr/lib/systemd/system` вместе с остальным содержимым пакета

#### Scenario: Отключение установки юнитов опцией
- **WHEN** сборка конфигурируется с `-DH1_INSTALL_SYSTEMD_UNITS=OFF` и пакет собирается
- **THEN** файлы юнитов не входят в пакет, остальной состав (`h1Server`, конфиг `/etc/h1/h1-server.env`) не меняется

### Requirement: Конфигурация окружения как conffile
Файл `/etc/h1/h1-server.env` SHALL быть зарегистрирован в списке conffiles
пакета: dpkg SHALL сохранять правки пользователя при обновлении пакета и
SHALL сообщать о конфликте вместо молчаливой перезаписи.

#### Scenario: Правки сохраняются при обновлении
- **WHEN** пользователь изменил `/etc/h1/h1-server.env` (реальные параметры БД и адрес сервера) и установил обновлённую версию пакета
- **THEN** правки сохраняются (dpkg оставляет пользовательскую версию или явно запрашивает решение о конфликте)

### Requirement: Автовключение юнита при установке и отключение при удалении
Пакет SHALL включать юнит `h1-server.service` в автозагрузку при установке
(`systemctl enable` в postinst) и отключать при удалении пакета
(`systemctl disable` в prerm), чтобы после удаления не оставались
висячие ссылки автозагрузки.

#### Scenario: Юнит в автозагрузке после установки
- **WHEN** пакет установлен на машине с работающим systemd
- **THEN** `systemctl is-enabled h1-server` отвечает `enabled`

#### Scenario: Автозагрузка снята при удалении
- **WHEN** выполняется удаление пакета
- **THEN** юнит выведен из автозагрузки до удаления файла юнита; после удаления `systemctl is-enabled h1-server` не отвечает `enabled`

### Requirement: Актуальность состояния systemd при установке и удалении
Пакет SHALL выполнять `systemctl daemon-reload` после установки/обновления и
после удаления, чтобы systemd сразу видел добавленные или удалённые юниты
без ручной перезагрузки демона.

#### Scenario: Юнит виден сразу после установки
- **WHEN** пакет установлен на машине с работающим systemd
- **THEN** `systemctl start h1-server` работает без предварительного ручного `daemon-reload`

#### Scenario: Юнит исчезает сразу после удаления
- **WHEN** выполняется удаление пакета на машине с работающим systemd
- **THEN** файл `h1-server.service` удалён из `/usr/lib/systemd/system` и systemd больше не видит юнит без ручного `daemon-reload`

### Requirement: Зависимости пакета
Пакет SHALL объявлять `Depends: libpq5` и НЕ объявлять зависимостей от
FetchContent-библиотек (spdlog, nlohmann/json, argparse, libenvpp) — они
должны быть линкованы статически. PostgreSQL-сервер не является зависимостью:
БД может быть внешней.

#### Scenario: Установка разрешает зависимости
- **WHEN** пакет устанавливается на системе Ubuntu без локального PostgreSQL-сервера
- **THEN** установка выполняется успешно; apt при необходимости устанавливает только `libpq5`

#### Scenario: Отсутствие сетевого доступа к БД не ломает установку
- **WHEN** пакет установлен на машине без работающего PostgreSQL
- **THEN** установка завершается успешно; сообщение об ошибке подключения появляется только при запуске приложения с операцией, требующей БД

### Requirement: Установка через apt-get на целевых платформах
Пакет SHALL корректно устанавливаться командой
`apt-get install ./h1-server_<версия>_amd64.deb` на Ubuntu 22.04 LTS и
Ubuntu 24.04 LTS (amd64), включая удаление `apt-get remove h1-server` без
оставшихся файлов.

#### Scenario: Установка на Ubuntu 22.04
- **WHEN** пакет устанавливается через `apt-get install ./h1-server_*.deb` на Ubuntu 22.04 amd64
- **THEN** установка завершается без ошибок, `/usr/bin/h1Server` на месте и `h1Server --help` работает

#### Scenario: Установка на Ubuntu 24.04
- **WHEN** пакет устанавливается через `apt-get install ./h1-server_*.deb` на Ubuntu 24.04 amd64
- **THEN** установка завершается без ошибок, `/usr/bin/h1Server` на месте и `h1Server --help` работает

#### Scenario: Удаление пакета
- **WHEN** выполняется `apt-get remove h1-server`
- **THEN** `/usr/bin/h1Server` удаляется, пакет исчезает из списка установленных

### Requirement: Установленный пакет работает как приложение из репозитория
Установленный пакет SHALL вести себя идентично серверному бинарнику,
собранному из исходников: поддерживает `--help`, `--host`, `--port`,
`--threads`, `--verbose`, обслуживает `POST /h1/task` и записывает историю
операций в доступный PostgreSQL.

#### Scenario: Расчет через установленный бинарник
- **WHEN** после установки запущен `h1Server` и клиент отправляет `POST /h1/task` с операцией `{"left": 2, "right": 3, "operation": "+"}`
- **THEN** сервер возвращает HTTP 200 и JSON с результатом `5`, как сервер из исходников

#### Scenario: Ошибка вычисления
- **WHEN** через установленный сервер выполняется операция с ошибкой (например деление на ноль)
- **THEN** сервер возвращает HTTP 500 и JSON с текстом ошибки, как сервер из исходников

### Requirement: Серверный systemd-юнит
Пакет SHALL содержать юнит `h1-server.service`, который запускает серверный
бинарник и читает параметры подключения к PostgreSQL и параметры сервера из
`/etc/h1/h1-server.env`. Юнит SHALL запускаться как долгоживущий сервис,
перезапускаться при аварийном завершении и останавливаться по
`systemctl stop h1-server`.

#### Scenario: Запуск сервера через systemctl
- **WHEN** на машине с доступным PostgreSQL и настроенным
  `/etc/h1/h1-server.env` выполняется `systemctl start h1-server`
- **THEN** сервис переходит в состояние `active (running)` и принимает
  HTTP-запросы на настроенном адресе

#### Scenario: Остановка сервера
- **WHEN** выполняется `systemctl stop h1-server`
- **THEN** сервис завершается штатно и переходит в состояние `inactive (dead)`

#### Scenario: Автозапуск после перезагрузки
- **WHEN** пакет установлен и машина перезагружена
- **THEN** сервис `h1-server` запускается автоматически (enabled)
