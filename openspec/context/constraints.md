# Обязательные ограничения проекта (из заданий ДЗ)

Эти ограничения формулированы в заданиях (`docs/task2.md`, `docs/task3.md`)
и обязательны для любых новых изменений:

1. **Запрещена многопоточность** — в исходниках не должно быть потоков,
   mutex-ов, async API.
2. **Запрещены сырые указатели** — все сырые указатели должны быть обернуты
   в умные указатели. Допустимое исключение — неизбежная C-API граница
   (libpq: `PGconn*`, `PGresult*`, `const char*`; сигнатура
   `main(int argc, char* argv[])`). Новые сырые указатели вне этих границ
   недопустимы.
3. **libpqxx запрещен** — работа с PostgreSQL только через собственную
   минимальную обертку над libpq (`h1::db::pg`).
4. **RAII** — все классы-обертки ресурсов должны поддерживать идиому RAII.
5. **Кеш**:
   - `std::unordered_map`, размер не ограничен;
   - ключ — нормализованное представление операции: "1+2" и "2+1" —
     идентичные операции (нормализация для коммутативных `+` и `*`);
   - при старте приложение прогревает кеш из БД (задание требует считывать
     всю доступную историю; известная недоработка — лимит выборки);
   - cache hit не выполняет повторный расчет; cache miss записывает результат
     в кеш и в БД.
6. **Логгер** — код не должен раскрывать детали реализации: пользовательский
   код не знает про `spdlog::logger`; доступ только через проектный интерфейс
   (макросы `H1_LOG_*`, паттерн Singleton Мейерса).
7. **JSON-вход** — данные передаются JSON-строкой через CLI (`--config`);
   парсинг — nlohmann/json; `--help` обязан работать.
8. **Тесты** — GoogleTest; тесты проверяют наблюдаемое поведение программы,
   а не детали реализации.
9. **Ресурсы/память** — проверять Valgrind (`--error-exitcode=42`) при
   изменениях во владении ресурсами; производительность анализировать Perf.

## Известные недоработки (из docs/task3_check.md)

Могут стать основой для новых изменений:

- нет отдельных тестов PostgreSQL-обертки, БД, кеша, cache hit/miss,
  коммутативности "1+2"=="2+1";
- прогрев кеша ограничен лимитом выборки (история свыше лимита не загружается);
- `DBManager::getData()` читает записи без `ORDER BY` (недетерминированный
  набор прогрева);
- Valgrind-скрипт не проверяет код возврата (опечатка `valgrid` в имени);
- результаты Perf и демонстрации (psql, видео) не сохранены в репозитории.
