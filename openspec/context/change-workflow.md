# Изменения как миграции: нумерация и хеши

Все изменения (OpenSpec changes) ведутся как миграции: у каждого — свой
уникальный порядковый номер и уникальный хеш, изменения идут строго
сверху вниз по проекту (по возрастанию номера).

## Формат имени change

```text
NNNN-<hash>-<kebab-name>
```

- `NNNN` — 4-значный порядковый номер миграции: `0001`, `0002`, `0003`, ...
- `<hash>` — уникальный короткий хеш (8 hex-символов), например первые
  8 символов md5 от имени change + даты создания. Хеш не повторяется
  между изменениями.
- `<kebab-name>` — понятное имя изменения (например `add-deb-package`).

Пример: `0001-dc9e0c15-add-deb-package`.

## Правила

1. **Номера идут строго по возрастанию.** Новый change обязан получить
   номер `max(существующих) + 1` — то есть располагаться НИЖЕ текущего
   (последнего) в каталоге `openspec/changes/`. Пропуски номеров и
   переиспользование номеров запрещены.
2. **Хеш уникален** для каждого change (включая архивированные — см.
   `openspec/changes/archive/`); нельзя использовать хеш уже
   существовавшего изменения.
3. **Имя change не меняется после создания** (кроме первоначального
   приведения к миграционному формату); переименование — только явным
   решением пользователя.
4. Перед созданием нового change агент ОБЯЗАН посмотреть существующие
   каталоги `openspec/changes/` (и `archive/`) и вычислить следующий
   номер + уникальный хеш.
5. В архиве изменения сохраняют свои имена/номера — хронология
   миграций остается читаемой.

## Как создать change по конвенции

```bash
# 1. Посмотреть существующие номера
ls openspec/changes/ openspec/changes/archive/

# 2. Вычислить номер и хеш (пример)
N=$((максимальный_номер + 1)); printf '%04d' "$N"
echo -n "<kebab-name>-$(date +%F)" | md5sum | cut -c1-8

# 3. Создать change сразу с полным именем
openspec new change "0002-<hash>-<kebab-name>"
```
