

# ДЗ-2. Практика

В этом ДЗ тебе предстоит переписать приложение с использованием парадигмы ООП — тебе необходимо превратить свободные функции в объекты.

## Задание
- Переписать проект в парадигме ООП
- Входные данные необходимо подавать в формате JSON https://www.json.org/json-ru.html Для парсинга JSON необходимо использовать библиотеку https://github.com/nlohmann/json 
  Внимание: json с данными передается в виде строки через параметры командной строки. Предыдущий механизм получения данных через аргументы командной строки можешь удалить. Флаг `--help` должен по-прежнему работать и выводить краткую справку по работе с утилитой.
- Добавить unit-тесты. Для тестов необходимо использовать библиотеку Google Test https://github.com/google/googletest Помни: тесты должны проверять наблюдаемое поведение программы, не нужно тестировать детали реализации
- Добавить логирование с помощью библиотеки spdlog https://github.com/gabime/spdlog. Для работы с объектом логгера необходимо использовать паттерн Singleton (Мейерса). Внимание: твой код не должен раскрывать детали реализации логгера, т.е. пользовательский код не должен знать, что под капотом в логгере используется spdlog::logger.

В качестве варианта архитектуры приложения ты можешь использовать следующий концепт:
```cpp
namespace calculator
{

struct Task
{
    int firstValue{0};
    int secondValue{0};
    char operation{'\0'};
    int result{0};
    int status{0};
};

class Application
{
  public:
    void run(int argc, char** argv)
    {
        getTask(argc, argv);
        makeCalculate();
        printResult();
    }

  private:
    void getTask(int argc, char** argv)
    {}

    void makeCalculate()
    {}

    void printResult() const
    {}

  private:
    Task task_;
};

} // namespace calculator

int main(int argc, char** argv)
{
    calculator::Application application;
    application.run(argc, argv);
}
```

## Требования
- Функционал, написанный при выполнении ДЗ-1 должен сохраниться в полном объеме, т.е. наблюдаемое поведение (проверки деления на 0, отрицательного факториала/степени, переполнения и т.д.) должно остаться прежним
- Допускается использование STL
- Начиная с этого ДЗ в основном коде проекта запрещено использовать свободные функции. Отдельная header-only библиотека математических функций из ДЗ-1 не подпадает под это ограничение — она остаётся без изменений, в C-стиле (свободные функции, коды возврата), исключения внутри неё использовать не нужно
- Запрещено использовать пользовательские глобальные переменные
- Для обработки ошибок в коде приложения (`Application`) необходимо использовать исключения. Поле `статус_выполнения_операции` в структуре `Task` из ДЗ-1 нужно сохранить — оно понадобится в дальнейших ДЗ
- Для работы над этим ДЗ необходимо создать отдельную ветку в уже имеющемся репозитории
- Начиная с этого ДЗ для именования коммитов необходимо использовать рекомендации документа https://www.conventionalcommits.org/ru/v1.0.0/ Дополнительно почитай про версионирование релизов https://semver.org/lang/ru/
- После окончания работы над ДЗ необходимо сделать PR и добавить ментора в ревьюеры
